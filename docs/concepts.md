# RAG 概念小抄

本页假设你第一次接触向量检索。把它当作 README 的配套词典；程序的实际默认值以 README 和源代码为准。

## 从文字到回答

**Token（令牌）**是模型处理文字时使用的基本单位，可能是一个字、一个词的一部分或标点。模型的 context window（上下文窗口）是一次请求能看到的 token 总量；PDF 片段、问题、系统指令和回答都可能占用它。字符数不等于 token 数，因此“1200 字符”不是“1200 token”。

**Chunk（片段）**是送进嵌入模型的一小段文本。项目按每页提取的文字切成最多 1200 个字符；**overlap（重叠）**为 200 个字符，意味着相邻片段共享结尾/开头，减少一句话刚好跨边界时的信息损失。片段太小会丢上下文，太大则检索不精确并更快填满上下文窗口。

**Embedding（嵌入）**是把文字映射成数字数组的过程，结果叫向量。语义相近的文字通常更接近，但不是严格的事实数据库。文档片段和问题必须使用同一个 embedding model（嵌入模型）；项目默认使用 `nomic-embed-text` 或 OpenAI 的 `text-embedding-3-small`。

## 余弦相似度

项目用两个非零向量夹角的余弦判断相似程度：

```text
cosine_similarity(a, b) = (a · b) / (||a|| × ||b||)
```

其中 `a · b` 是点积，`||a||` 是向量长度（代码里通常写作 `sqrt(sum(x²))`）。值越接近 1，方向越相似；值接近 0 表示方向差异大。它不等于“答案正确率”，只是排序信号。

二维例子：假设问题向量 `q = (1, 1)`，两个片段向量分别为 `d₁ = (1, 0)`、`d₂ = (0.8, 0.8)`。则：

```text
cos(q, d₁) = (1×1 + 1×0) / (√(1²+1²) × √(1²+0²)) ≈ 0.707
cos(q, d₂) = (1×0.8 + 1×0.8) / (√2 × √(0.8²+0.8²)) = 1.000
```

所以 `d₂` 排在 `d₁` 前面。真实模型的向量通常有数百或数千维，程序在 [`retrieval.py`](../src/beginner_pdf_rag/retrieval.py) 中用 NumPy 做同样的计算。

## 检索和生成

**Top-K** 是保留分数最高的 K 个片段；默认 K 为 3。K 太小可能漏掉关键段落，K 太大则会加入噪声并消耗 context window。`--top-k 5` 可以在命令行临时改成 5。

**Prompt（提示词）**是发送给 chat model（对话模型）的指令和输入。本项目把问题、片段和 `[Page N | score=...]` 标记放入 prompt，并要求只根据上下文回答；这是一种约束，不是安全证明。

**Hallucination（幻觉）**是模型生成了输入中没有充分支持的内容。即使检索正确，模型也可能误读、拼接或过度推断；“我找不到”提示能降低风险，但不能消除风险。务必打开页面核对。

整体顺序是：PDF → 页面文本 → chunks → embeddings → 问题 embedding → cosine similarity → Top-K context → chat model → 带页码的回答。README 的 Mermaid 图展示了同一条路径。
